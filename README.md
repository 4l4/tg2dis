# tg2disbot

Копирует посты (текст + вложения) из Telegram-канала в Discord.

- **Telegram** читает **бот** (Bot API, `getUpdates`) — бот должен быть админом канала-источника.
- **Discord** публикует **бот** (Bot API) в указанный канал.
- Файлы **≤ 20 МБ** пересылаются вложением. Файлы **> 20 МБ** заменяются **ссылкой** на исходный пост (Telegram Bot API не умеет скачивать файлы больше 20 МБ).
- Поддерживаются альбомы (несколько медиа одним постом) и длинный текст (режется под лимит Discord 2000 символов).

### Какие типы постов переносятся

| Тип в Telegram | Как приходит в Discord |
|---|---|
| Текст, фото, видео, документы, аудио, GIF | текст + вложения (альбом — до 10 файлов в сообщении) |
| **Кружок** (видео-сообщение) | обычное видео `.mp4` (играет инлайн) |
| **Голосовое сообщение** | нативное voice message с плеером; если Discord откажет боту — обычное `.ogg`-вложение |
| **Опрос** | нативный опрос Discord, таймер по умолчанию 24ч (`POLL_HOURS`) |

> Форму волны для голосовых Bot API не отдаёт — в плеере Discord она рисуется заглушкой (на воспроизведение не влияет). Telegram-квизы переносятся как обычные опросы (Discord не поддерживает «правильный ответ»).
- Хостится **бесплатно на GitHub Actions** (long polling, почти мгновенно) — свой сервер не нужен.

## Шаг 1. Создать Telegram-бота (@BotFather)

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram → команда `/newbot`.
2. Задайте имя и username бота → BotFather пришлёт **токен** вида `123456:ABC...` — это `TG_BOT_TOKEN`.
3. Откройте свой канал-источник → **Управление каналом → Администраторы → Добавить** → добавьте вашего бота администратором.
   Как админ канала бот автоматически получает все посты (`channel_post`), никаких доп. настроек privacy не требуется.

> **ID канала (`TG_SOURCE_CHAT_ID`, необязательно).** Если бот добавлен только в один канал — можно не указывать. Иначе задайте `@username` канала (для публичных) или числовой `-100...` id. Узнать числовой id: перешлите любой пост канала боту [@userinfobot](https://t.me/userinfobot).

## Шаг 2. Создать Discord-бота

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application** → введите название.
2. Вкладка **Bot** → **Reset Token** → скопируйте **токен** — это `DISCORD_BOT_TOKEN`.
3. Пригласите бота на сервер: вкладка **OAuth2 → URL Generator** →
   - в *Scopes* отметьте `bot`,
   - в *Bot Permissions* отметьте **Send Messages** и **Attach Files**,
   - скопируйте ссылку внизу, откройте её в браузере и добавьте бота на свой сервер.
4. Узнайте ID канала: в Discord включите **Настройки → Расширенные → Режим разработчика**, затем ПКМ по нужному текстовому каналу → **Copy Channel ID** — это `DISCORD_CHANNEL_ID`.

## Шаг 3. Развернуть на GitHub (бесплатно)

Бот работает в **GitHub Actions** (это не GitHub Pages — Pages только для статичных сайтов и здесь не подходит).

1. Создайте репозиторий и залейте в него этот проект. Лучше **public** — тогда минуты Actions безлимитны (в private — лимит 2000 мин/мес).
2. В репозитории: **Settings → Secrets and variables → Actions → New repository secret** и добавьте секреты:
   - `TG_BOT_TOKEN`
   - `DISCORD_BOT_TOKEN`
   - `DISCORD_CHANNEL_ID`
   - `TG_SOURCE_CHAT_ID` (если нужен — иначе не создавайте)
3. Готово. Workflow `.github/workflows/mirror.yml` уже в проекте. Запустите цепочку вручную один раз: **Actions → tg2dis mirror → Run workflow**.

Как это работает (без сторонних сервисов):
- Один прогон держит **long polling** (`getUpdates` с длинным таймаутом) ~5.5 часа и получает посты **почти мгновенно** — задержка секунды, а не минуты.
- `concurrency` не даёт двум прогонам идти внахлёст и ставит следующий **встык**, так что опрос непрерывный. Встроенный cron (`schedule`) нужен лишь чтобы восстановить цепочку, если она оборвётся.
- Дублей нет: Telegram сам не отдаёт уже подтверждённые апдейты (offset). Транзиентные сетевые сбои цикл переживает без падения.
- ⚠️ Расписание GitHub **отключается после 60 дней без активности** в репозитории — иногда делайте коммит или запускайте вручную.

## Мониторинг и логи

- Логи каждого прогона: вкладка **Actions → нужный run → шаг «Run python poll_bot.py»**.
  Там видно `[send] ...` по каждому посту, `[ok] обработано постов: N`, а также `[warn]/[info]` и ошибки.
- Ошибка на стороне **Telegram** или **Discord** помечает прогон как **упавший** (красный). GitHub по умолчанию
  присылает письмо о падении scheduled workflow — то есть о проблемах вы узнаете без ежедневного чтения логов.
- Голосовое, которое Discord не принял как voice message, не считается ошибкой: в логе будет `[warn] voice ... фолбэк`,
  и оно уйдёт обычным `.ogg`-вложением.

## Запуск локально (для проверки, необязательно)

```bash
pip install -r requirements.txt
cp .env.example .env      # заполнить токены
python poll_bot.py        # разовый прогон: заберёт накопившиеся посты и отправит в Discord
```

## Переменные окружения

| Переменная | Обяз. | Описание |
|---|---|---|
| `TG_BOT_TOKEN` | да | токен Telegram-бота от @BotFather |
| `DISCORD_BOT_TOKEN` | да | токен Discord-бота |
| `DISCORD_CHANNEL_ID` | да | ID текстового канала Discord для постинга |
| `TG_SOURCE_CHAT_ID` | нет | фильтр канала-источника: `-100...` или `@username` |
| `MAX_FILE_MB` | нет | порог размера файла, по умолчанию 20 |
| `POLL_HOURS` | нет | длительность опроса в Discord (часы), по умолчанию 24 |

## Ограничение

Бот видит только те каналы, где он **администратор**. Зеркалить чужой канал, которым вы не управляете и куда бота не добавить, таким способом нельзя.
